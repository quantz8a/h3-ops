最佳实践

引擎能跑 ≠ 产线能连。下面是 h3-opt 的默认约定。

1. 先 doctor，再跑。 绿灯才出片；不要和 mlx-serve / 另一 ./h3 对打——统一内存假死比慢更糟。
2. 迭代默认 snap / warm。 Do：h3ctl warm --preset snap 常驻后再抽；或 snap → draw → preview → film_*。Don't：一上来 hero。
3. 拆墙钟。 snap* 自动 --profile；看 report 的 denoise_s vs wall_s。冷启动瓶颈是 TE+DiT load。
4. ≥64GB 默认常驻。 大内存 不要开 --ssd-streaming（更慢）。低内存机才默认 SSD。
5. FL2VA ≠ Ref2VA（互斥）。 锁动作起止 → --first-frame / --last-frame。锁人物身份 → --ref-image（定妆）。不要混用。
6. 接戏用尾帧。 上一镜结束帧 → 下一镜 --first-frame。每镜独立抽卡 = 换脸、换光、换片场。
7. 三锁写进 ContextDoc。 身份 / 场景 / 动作可 revise；MP4 只是投影。先 cir validate，再 ops.run。
8. 横幅走 film 阶梯。 film_draft（832×480 抽卡）→ film_master（1248×704 成片）→ film_hero（高潮少用）。
9. HD 标签诚实。 native · upscale_* · cloud_2k——不装本地 2K。
10. 工厂调 h3ctl。 不要散装拼裸 ./h3（cwd / shaders / lock 全靠个人记性）。

先 doctor，再 warm/snap，过了再爬档；≥64GB 不开 SSD；锁人用 Ref，锁态用首尾，接戏用尾帧。

git clone https://github.com/quantz8a/h3-ops.git && cd h3-ops
python3 -m venv .venv && source .venv/bin/activate
python -m pip install -e .
export H3_OPS_H3C_SRC=/path/to/h3.c
export H3_OPS_MODEL_DIR=/path/to/MiniMax-H3
h3ctl doctor
h3ctl run --preset snap --prompt-file examples/smoke.prompt.txt -o out/snap.mp4 --profile
